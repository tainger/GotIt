# 自用短视频下载工具规划

> 需求来源：本次对话。用户希望粘贴抖音等平台分享链接获取视频，自用、低成本，暂不商业化。
> ⚠️ raw 缺失，待补充：当前仓库没有原始笔记。以下是待验证的设计方案和预算假设，不是已经实现或实测的能力。

## 目标与范围

- 产品定位：本地运行的短视频链接解析与下载工具。
- 首期平台：抖音公开单条视频，供本人有权保存的素材使用。
- 首期路径：粘贴完整分享文案 → 提取链接 → 解析 → 下载到电脑 → 查看结果。
- “去水印”指获取来源提供的无水印文件，不包含 AI 擦除已嵌入画面的水印；实际效果需验证。
- 设备偏好尚未确认，暂以电脑下载为第一阶段验收目标；架构预留手机浏览器访问。
- 首期不做微信小程序、账号系统、支付、广告、批量采集、图集、直播和私密视频。

## 选型结论

| 部分 | 首期方案 | 原因 |
| --- | --- | --- |
| 页面 | 本地 HTML/CSS/JavaScript | 页面简单，无需前端构建体系 |
| 后端 | Python + FastAPI | 接收链接、调用解析器、流式下载 |
| 解析 | 可替换适配器，先验证一个来源 | 隔离供应商或平台变化 |
| 文件 | 本机 downloads 目录 | 不支付云存储和云下载流量费用 |
| 记录 | 本地 JSON，任务状态先存内存 | 自用低并发无需独立数据库 |
| 部署 | 本机进程，一条命令启动 | 无需服务器和 GPU |

程序代码应放在独立应用目录；本页仅规划，不在 raw 笔记中添加或修改实现代码。

## 解析来源选择

1. 先评估一个维护中的开源解析器：许可证、近期维护情况、依赖、是否要求登录态。
2. 用本人提供的真实链接在本机验证，不将“项目声称支持”视为可用证据。
3. 如果需要频繁维护、复杂登录配置或无法稳定下载，则选择小额按次 API。
4. API 接入前核对最低充值额、失败计费、实际下载地址、时效、支持格式和隐私处理。
5. 首期只接一个可用来源，保留统一接口，不提前实现多个备用供应商。

选择原则：开源方案降低调用费；按次 API 降低维护投入。先通过小规模测试再决定，暂不购买套餐。

## 数据流与接口草案

分享文案 → 提取并校验平台链接 → 解析适配器 → 视频元信息 → 下载任务 → 本地文件。

- `POST /api/resolve`：输入分享文案，返回结果 ID、标题、来源平台、可用格式。
- `POST /api/download`：输入结果 ID，创建下载任务，不接受客户端任意下载 URL。
- `GET /api/tasks/{id}`：返回等待、下载中、完成、失败等状态和已下载字节数。
- `GET /api/files/{id}`：按文件 ID 获取已完成文件。
- 解析器统一输出：平台、视频 ID、标题、下载 URL、必要请求头、已知有效期。
- 下载前地址失效时允许重新解析一次；不无限重试。
- 无总大小时只显示已下载量，不显示虚构百分比。

## 实现约束

- 默认只监听本机地址；手机同 Wi-Fi 访问作为显式开启选项，增加访问口令。
- 链接、重定向和下载目标逐级校验，禁止访问内网、回环和云元数据地址。
- 首期默认单任务下载，文件上限 200MB；超时与大小均可配置。
- 下载使用临时文件，完成后改名；失败清理残留，标题净化后用视频 ID 防重名。
- API 密钥及可选登录态保存在本地配置，排除版本管理，日志不记录这些值。
- 下载时流式写盘，避免把完整视频加载到内存；验证返回的是视频而不是错误网页。
- 手机访问和相册保存单独验收，不将“浏览器能下载”等同于“可直接存入相册”。

## 分阶段执行与验收

### 阶段一：验证解析与下载链路

- 选择解析来源并记录版本、费用与配置方式。
- 使用 10～20 条本人有权保存的抖音链接，覆盖短链接、完整文案和长短视频。
- 验证文件可播放、有声音、下载完整；人工确认是否含水印。
- 记录解析成功和完整下载成功两个指标，记录失败原因及实际耗时。
- 建议继续条件：至少 90% 的有效测试链接完成下载；这是项目目标，不是能力承诺。
- 未达到目标时先更换或修复解析来源，暂不投入页面开发。

### 阶段二：本地最小可用版

- 增加粘贴框、解析按钮、标题和下载状态、结果入口。
- 提供启动说明和配置示例，不要求用户手动调用接口。
- 验证非法链接、失效链接、网络中断、超限文件、重复下载和磁盘写入失败。
- 验收：从粘贴到拿到可播放文件完整走通，失败时说明原因，无残留半成品文件。

### 阶段三：按真实需要扩展

- 手机优先：同 Wi-Fi 访问，分别验证 iOS/安卓下载与相册保存流程。
- 多平台优先：先加快手或小红书中的一个，复用同一套验收流程。
- 只有出现外出使用需求后，才评估私人远程访问或云部署。

## 成本与时间预算

⚠️ raw 缺失，待补充：下列金额为规划假设，未选定供应商，不能当作报价。

| 项目 | 预算 |
| --- | --- |
| 本地部署 | 无新增云资源账单，使用现有电脑、网络和电力 |
| 开源解析 | 不预设调用费，但有维护成本；需核实项目与依赖条件 |
| 按次 API | 假设 0.01～0.05 元/次，每天 10 次，每月约 3～15 元 |
| 初次验证 | 建议充值上限 20 元；最低充值超预算则换来源 |
| 云服务器、对象存储、GPU | 首期均不购买 |

月 API 费 = 实际计费调用次数 × 单价；失败重试及最低充值额可能增加支出。

时间估计：链路验证半天至一天；解析来源稳定后，本地页面与异常处理约 1～2 天；手机适配另行验证。

## 下一步

进入实现前确认主要保存设备，并准备几条用于验收的公开分享链接。
默认继续方案：电脑端本地工具，先验证开源来源，必要时切换小额 API，不部署云服务。
